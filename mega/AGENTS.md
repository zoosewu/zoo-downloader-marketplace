# zoo-downloader site module

This directory is a **site module** for zoo-downloader, a download manager. When a user pastes
a share-page URL that matches `urlPatterns` in `manifest.json`, the app runs this module's
`resolve(url, zoo)` and downloads the direct file URL it returns.

Your job is usually: given a site, make `resolve` turn its share pages into direct downloads.

## Files

| Path | What it is |
|---|---|
| `src/index.ts` | The module. Edit this. |
| `manifest.json` | Id, name, which URLs it handles (`urlPatterns`), what it may access (`permissions`). Schema: `types/manifest.schema.json`. |
| `dist/index.js` | The bundle the app runs. Generated by `pnpm build`; never edit it. |
| `tests/cases.json` | Test cases: share-page URLs and what their result must look like. |
| `tests/cassettes/` | Recorded site responses, one file per case. Generated by `zoo-module test --record`. |
| `types/` | The API (`zoo-module.d.ts`), the global Web APIs that exist (`globals.d.ts`), the manifest schema. Read them; they are the reference. Do not edit. |
| `.credentials.json` | Your own account for testing, `{ "username": "...", "password": "..." }`. Git-ignored; never commit or print it. |

## Workflow

```sh
pnpm install                 # once
pnpm build                   # src/index.ts -> dist/index.js
pnpm typecheck               # types: catches unsupported APIs and wrong result fields
zoo-module check             # manifest, bundle, test cases
zoo-module test --record     # run every case against the real site and record it
zoo-module test              # replay the recordings offline (fast, repeatable)
zoo-module test --json       # the same, as JSON
zoo-module test --url <URL>  # try one URL against the real site
```

Repeat **edit → build → typecheck → test** until every case passes. Record again
(`--record`) only when you need new responses from the site (for example after the module
starts requesting a page it did not request before; the test output tells you).

## Hard rules

- **One file.** The bundle may import only `zoo-module`. `pnpm build` bundles npm packages you
  add, so libraries are fine as long as they need nothing beyond the globals below.
- **Web APIs only.** Available: `fetch`, `Headers`, `Response`, `FormData`, `URL`,
  `URLSearchParams`, `DOMParser`, `TextEncoder`/`TextDecoder`, `atob`/`btoa`, `crypto`
  (random values, `subtle.digest`), timers, `AbortController`, `structuredClone`, `console`.
  Not available: `document`, `window`, `localStorage`, `XMLHttpRequest`, `WebSocket`, `Blob`,
  Node (`require`, `process`, `fs`, `Buffer`) and Deno. `pnpm typecheck` flags these.
- **Network allowlist.** `fetch` can only reach hosts listed in
  `manifest.json` → `permissions.network.allowDomains` (subdomains included; CDN hosts the
  file is served from too). Anything else fails with a message naming the host to add.
  Local and private addresses are always blocked.
- **No state between calls.** Every call starts fresh; cookies last for one call.
- **Limits.** 30 seconds of work per call (countdowns and captchas excluded), 128 MB memory,
  16 MB per response.
- **Which URLs.** `urlPatterns` (`*` wildcards) decide which links reach the module; list
  every host form. When a wildcard is too broad, add `urlRegex` (Rust regex syntax: no
  lookaround or backreferences): a URL must match both. Matching never runs module code.
- **`autoStart`.** `true` lets a copied link start downloading without the add-download page,
  when the user allows it. Leave it out for sites that usually ask for a captcha or a wait.
- **Result fields** are exactly `url`, `filename`, `headers`, `size`, `maxConnections`,
  `maxSegmentSize` (see `Resolved` in `types/zoo-module.d.ts`). Unknown fields are an error.
- **Links with several files** (shared folders) also export `list(url, zoo)`: one
  `{ url, filename, size?, folder? }` per file (see `Listed`), at most 1000. The app shows them
  for the user to pick; each picked file becomes a download whose URL is the item's `url`, so
  `resolve` must turn that URL into just this file. The item URL must match `urlPatterns` and
  hold no credential placeholders.

## Recipes

**Find the link on the page**

```ts
const page = await fetch(url);
const doc = new DOMParser().parseFromString(await page.text(), 'text/html');
const href = doc.querySelector('a#download')?.getAttribute('href');
if (!href) throw zoo.fail('download link not found', { hint: 'the page layout may have changed' });
return { url: new URL(href, page.url).href };
```

**JSON API**: `const data = await (await fetch(api, { method: 'POST', headers: { 'Content-Type': 'application/json' }, body: JSON.stringify({ id }) })).json();`

**Log in.** Declare the fields in `manifest.json` (`permissions.credentials`), then use
placeholders. You never see the values; the host substitutes them in requests.

```ts
if (zoo.credentials.has('password')) {
  await fetch('https://site.example/login', {
    method: 'POST',
    body: new URLSearchParams({
      user: zoo.credentials.placeholder('username'),
      pass: zoo.credentials.placeholder('password'),
    }),
  });
}
```

Placeholders work in URLs, headers, form and JSON bodies. Do not transform them (`btoa`,
slicing, hashing): the host will not recognize the result.

Tell the user how to get each value when it is not obvious (a cookie, an API key):
`credentialsHelp` shows above the fields, a field's `help` under it, and `credentialsHelpUrl` /
`helpUrl` (https) link to a longer guide. `label` and the help texts take one string or one per
language; line breaks (`\n`) and spaces show as written:

```json
"credentialsHelp": { "en": "Sign in at example.com first.", "zh-TW": "先在瀏覽器登入 example.com。" },
"permissions": {
  "credentials": [{
    "key": "session", "label": { "en": "Session cookie", "zh-TW": "Session cookie" },
    "help": { "en": "F12 → Application → Cookies → example.com: copy the Value of SESSION", "zh-TW": "F12 → 應用程式 → Cookie → example.com：複製 SESSION 的值" }
  }]
}
```

**Session cookies and Referer.** Cookies persist for the call automatically and are sent with
the download. Many sites also want the page as Referer:
`return { url: direct, headers: { Referer: page.url } };`

**Free-user countdown.** `await zoo.wait(30, 'free download countdown');` (replays skip it).

**Captchas.** `const token = await zoo.captcha.recaptcha({ siteKey, pageUrl: url });` or
`const text = await zoo.captcha.image(imageUrl);` The user solves it in the app; while
recording, `zoo-module test` asks you in the terminal.

**Every kind of link.** Users paste whatever their browser shows: the share page, the page a
site redirects to (a password or login step), mobile pages, older domains, `http://`, a folder
opened inside a share. Find them all (follow the site's redirects), list each in `urlPatterns`,
parse each in `resolve`, and give each a case in `tests/cases.json`; `zoo-module check` warns
about a pattern no case tries. Anything a link may lack (a password, a code) is asked with
`zoo.ask`, never a reason to fail.

**Something only the user knows** (an extraction code, a one-time login code):
`const code = await zoo.ask({ id: 'pwd', message: { en: 'Extraction code', 'zh-TW': '提取碼' }, remember: true });`
Each call is one dialog; ask again for the next step. `remember: true` keeps the answer for this
download, so retries and an expired link do not ask again; when the answer turns out wrong, ask
with `error: 'Wrong code'` (that always asks). Use `secret: true` for passwords. Needs
`"apiVersion": 3`. Values the user keeps for every download (an account) belong in manifest
`permissions.credentials`, not here.

**Files the server keeps encrypted** (MEGA: the key is in the link): return the key and let the
app decrypt as it downloads; never download the file yourself.
`return { url, filename, decrypt: { cipher: 'aes-128-ctr', key: hex(key), iv: hex(iv) } };`
The host's `crypto.subtle` only hashes: bundle a small AES library for anything the module must
decrypt itself (names, keys). Needs `"apiVersion": 4`.

**Transfer quotas** (HTTP 509 when the site's free allowance is used up): the app asks `resolve`
again when the download gets 509, and resumes where it stopped. Have `resolve` check whether the
site serves now (a one-byte `Range` request to the link) and `zoo.wait` out what the site says is
left before returning the link.

**Pretend to be the site's own downloader.** Some sites only serve their own client. Set its
User-Agent on `fetch` and in the result:
`return { url: dlink, headers: { 'User-Agent': 'netdisk;7.42.0.5;PC;PC-Windows;10.0.22631;WindowsBaiduYunGuanJia' } };`

**Sites that punish parallel downloads**: `return { url, maxConnections: 1 };`

**Sites that refuse large ranges** (403 for big `Range` requests, small ones work):
`return { url, maxSegmentSize: 4 * 1024 * 1024 };`

**Shared folders.** Give each file a URL of its own with a `#fragment` (matching and `fetch`
ignore it), and let `resolve` pick that file when the fragment is there:

```ts
export default defineModule({
  async list(url, zoo) {
    const files = await listShare(url); // [{ path: 'photos/a.jpg', size: 1 }, ...]
    return files.map((f) => ({
      url: `${url.split('#')[0]}#path=${encodeURIComponent(f.path)}`,
      filename: f.path.split('/').pop()!,
      folder: f.path.split('/').slice(0, -1).join('/') || undefined,
      size: f.size,
    }));
  },
  async resolve(url, zoo) {
    const path = new URL(url).hash.match(/^#path=(.*)$/)?.[1];
    // ...the direct link for decodeURIComponent(path), or for the only file when path is missing
  },
});
```

**Errors the user can act on**: `throw zoo.fail('file was deleted', { hint: 'ask the uploader for a new link' });`

## Reading `zoo-module test` output

| Output | Fix |
|---|---|
| `BLOCKED: x.com is not in the module's permissions.network.allowDomains` | Add `x.com` to `allowDomains` if the module really needs it. |
| `... is not in the cassette` | The module now requests something new: `zoo-module test --record`. |
| `credential 'k' is not available` | Declare `k` in `permissions.credentials`; for tests put it in `.credentials.json`. |
| `resolve returned an invalid result` | Return exactly the fields in `Resolved`. |
| `list returned ...` | Each item needs its own absolute `url` and a `filename`; fields are exactly those of `Listed`. |
| `FAIL listed url` | An item's `url` does not match `urlPatterns`; the app would refuse the whole list. |
| `resolve never settled` | A promise that never resolves; usually a missing `await` or a callback API. |
| `exceeded its 30000 ms time limit` | A loop that never ends or a request that never answers. |
| `module load failed: ... export named 'default'` | `export default defineModule({ async resolve(url, zoo) { ... } })` |
| `FAIL expect.url` | The result differs from `tests/cases.json`; `*` in expectations matches anything. |

## Test cases

`tests/cases.json` is a list of `{ "name", "url", "expect" }`. `expect.url` and
`expect.filename` are patterns (`*` matches anything; tokens in direct links change, so match
the stable part); `expect.error` is text the error must contain, for pages that should fail
(deleted files). Add a case per kind of page: normal, premium-only, deleted, folder.

For `list`, add `"list": true` to the case; `expect.count` is the number of files and
`expect.files` the `folder/filename` of each (any order), e.g.
`{ "name": "folder", "url": "...", "list": true, "expect": { "count": 2, "files": ["a.txt", "sub/b.txt"] } }`.
Add a `resolve` case for one listed file's `url` too.

Recordings contain the site's responses, which may include session cookies of the account you
recorded with (credential values themselves are never stored). Think before publishing them.
